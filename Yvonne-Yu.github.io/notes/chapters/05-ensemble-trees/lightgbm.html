LightGBM: Histograms, Sampling, and Leaf Growth

Learning goals

Explain how training reduces row and feature work, calculate GOSS weights, distinguish histogram construction from scanning, and control leaf-wise overfitting.

Intuition

Boosted-tree training repeatedly searches for good splits. The central computational levers are the number of rows processed, the effective feature count, the number of candidate thresholds, and the order in which leaves are expanded. LightGBM’s original contributions target those levers rather than replacing the overall additive-tree idea.

No fixed speed ratio follows from an algorithm name. Data sparsity, hardware, bin counts, objectives, and tuning determine observed runtime and memory.

Worked example

GOSS with an explicit sampling convention

With \(n=1000\), retain the largest-gradient fraction \(a=0.2\), or 200 rows. Draw \(bn=100\) rows from the remaining 800, where \(b=0.1\) is a fraction of the original sample size. Each sampled small-gradient row represents \(800/100=8\) rows, so multiply its contribution by \((1-a)/b=8\). The retained set has 300 rows.

If instead someone defines \(b\) as a fraction of the remaining rows, the weight is \(1/b\) and the sample size changes. Stating the convention prevents an otherwise plausible but wrong formula.

Bundling bins

Suppose feature A has nonzero bins 1–3 and feature B has nonzero bins 1–2, and they never coexist. Encode A’s bins as 1–3, B’s as 4–5, and all-zero as 0, while retaining feature/bin metadata. This stores sparse activity compactly. It is not equivalent to handing a generic tree an ordinal scalar and assuming every threshold preserves the original split semantics.

Theory and assumptions

GOSS: retain influential gradients

Large absolute gradients indicate observations to which the current loss is sensitive. GOSS retains that group and subsamples smaller gradients. For a candidate region,

\[\widehat G=\sum_{i\in A}g_i+\frac{1-a}{b}\sum_{i\in B}g_i.\]

Appropriate weighting recovers a gradient total in expectation under the sampling design. Implementations using second-order statistics apply their corresponding weighted statistics. Because gain contains squares and ratios, unbiased gradient totals do not imply exactly unbiased gain estimates. Sampling is an approximation with its own variance, not a guarantee of unchanged accuracy.

EFB: reduce sparse feature work

Exclusive Feature Bundling groups features whose nonzero occurrences rarely overlap. A conflict graph connects features with simultaneous activity; finding an ideal grouping is difficult, so a greedy procedure constructs bundles with controlled conflicts. Perfect exclusivity can preserve bin information, while tolerating conflicts introduces approximation. The goal is reducing effective histogram-building feature work, not inventing a meaningful order among original categories.

Histograms and subtraction

Map continuous values to a limited number of bins. At a node, aggregate gradient and Hessian totals per bin; scan prefix sums to evaluate thresholds. Candidate scanning is \(O(Bd)\) for \(B\) bins and \(d\) features, but accumulating the histogram still depends on the node’s rows. Gradients change each boosting round, so this is not a one-time \(O(n)\) cost for the whole training process.

A child histogram can be obtained by subtracting its sibling histogram from the parent histogram. Building the smaller child’s statistics and obtaining the larger one by subtraction saves work. Fewer bins reduce memory and candidate count but can merge meaningful distinctions.

Leaf-wise growth

Depth-wise growth expands available nodes at a common depth; best-first leaf-wise growth chooses the currently most promising leaf by gain. The latter spends a limited leaf budget where it helps immediately, but can create a very deep branch. It is greedy, so there is no universal global-optimality guarantee for the final tree.

Control both total leaves and support within each leaf. A depth limit \(D\) permits at most \(2^D\) leaves, but setting fewer leaves does not alone bound every path’s depth. Tree-growth policies are configuration choices; modern systems can support more than one policy.

Categorical features

Categorical splitting aggregates gradient and Hessian sums for each category, \(G_c=\sum_{i:x_i=c}g_i\) and \(H_c=\sum_{i:x_i=c}h_i\). A useful second-order ordering score is \(G_c/H_c\) when \(H_c>0\); implementations can smooth or regularize this ratio for sparse categories. Sort categories by that score, then evaluate contiguous cut points with the actual split-gain formula. For illustrative scores \(-1,0.5,2\), only the two cuts in the ordered list need evaluation, rather than every binary partition. The optimal-grouping argument depends on the split objective and its assumptions; it is not an unconditional guarantee for every categorical regularizer or constraint.

This approach avoids expanding every category into an independent sparse binary feature in suitable situations. It still uses training labels through gradients and requires regularization, proper train/validation separation, and handling of rare or unseen categories. It is not a blanket guarantee against label leakage.

The LightGBM feature reference describes histogram construction, histogram subtraction, leaf-wise growth, and categorical split support. Verify enabled sampling and categorical settings rather than assuming every optional mechanism runs in every fit.

The last two rows are distinct: a minimum sample count is not generally equivalent to a minimum Hessian sum. Pair num_leaves with minimum leaf support, optional maximum depth, regularization, and early stopping. Evaluate small-data overfitting empirically. GOSS, bagging, and categorical choices have version-dependent configuration; consult the actual API used.

Interview questions

What does GOSS save? It reduces rows used in split-statistic estimation by retaining large gradients and representing the rest with weighted samples.

What does EFB require? Sparse features with little simultaneous nonzero activity, plus metadata preserving bin interpretation.

Does a histogram eliminate scanning rows? No. It reduces threshold candidates; histogram construction still needs statistics from rows.

Why can leaf-wise trees overfit? Greedy expansion can concentrate many splits on a small region unless support and complexity are constrained.

Summary

Separate sampling, sparse storage, threshold approximation, and tree-growth policy. Each saves a different part of the computation and introduces a different tuning tradeoff.
