Random Forest: Averaging, Correlation, and OOB Evaluation

Learning goals

Derive ensemble variance, calculate the out-of-bag probability, explain feature importance, and tune tree strength against correlation.

Intuition

A deep tree can change sharply when its training sample changes. Bagging averages trees trained on bootstrap samples. Random forests add another source of randomness: at each split, search only a random subset of features. This prevents every tree from relying on the same strongest predictor at the top.

The trees are separately trainable, but their predictions are not statistically independent: they share the underlying dataset and signal.

Worked example

Suppose each tree’s prediction at a point has variance \(\sigma^2=0.09\), with pairwise correlation \(\rho=0.2\). For \(B=100\) trees,

\[\operatorname{Var}(\bar f)=0.2(0.09)+\frac{0.8}{100}(0.09)=0.01872.\]

With infinitely many such trees, the variance floor is still \(0.018\). Lowering correlation is therefore often more valuable than adding another hundred nearly identical trees.

For eight indexed observations, a bootstrap sample might be \((1,1,3,3,5,7,8,8)\). Its OOB set is \(\{2,4,6\}\). Repeated observations count repeatedly during tree fitting. Observation 1 must not receive an OOB prediction from this tree. A new observation is evaluated by every tree, whereas each training observation’s OOB score uses only eligible trees.

The three-tree admissions walkthrough makes the distinction concrete. Each row lists the sampled IDs and the IDs that tree did not see:

Tree Bootstrap IDs OOB IDs Illustrative rule
1 \(1,1,3,3,5,7,8,8\) \(2,4,6\) GPA \(>3.7\) votes Y; otherwise N
2 \(2,2,4,5,5,6,7,8\) \(1,3\) Recommendation \(\ge5\) and experience \(>1\) votes Y
3 \(1,3,3,4,4,6,7,8\) \(2,5\) GPA \(>3.55\) votes Y; otherwise N

For a new candidate with GPA \(3.8\), experience \(2\), and recommendation \(5\), all three illustrative rules vote Y, so the majority vote is Y. For training candidate 1, only Tree 2 is eligible for an OOB prediction; for candidate 2, Trees 1 and 3 are eligible. The original lecture example swaps these OOB memberships and uses GPA \(3.7\) with a strict \(>3.7\) rule while calling the vote Y. Those arithmetic details are corrected here. Three small trees also leave some rows with very few OOB votes, so the example illustrates mechanics rather than a reliable error estimate.

Theory and assumptions

For equal marginal variances and common covariance \(\rho\sigma^2\),

\[\begin{aligned} \operatorname{Var}(\bar f) &=\frac{B\sigma^2+B(B-1)\rho\sigma^2}{B^2}\\ &=\rho\sigma^2+\frac{1-\rho}{B}\sigma^2. \end{aligned}\]

This stylized calculation makes the strength–correlation tradeoff visible. Restricting features can lower correlation but also weaken individual trees.

Training and OOB prediction

For each tree, sample \(n\) rows with replacement, then at every node sample \(m\) candidate features and choose the best admissible split. Aggregate regression predictions by averaging. Classification may aggregate votes or averaged leaf class probabilities, depending on the algorithm and implementation.

The probability a given row is never selected is

\[P(\mathrm{OOB})=\left(1-\frac1n\right)^n\longrightarrow e^{-1}\approx0.368.\]

Thus a bootstrap sample contains about 63.2% distinct training rows on average; this is not a statement that two samples have exactly 63.2% overlap. For each row, average predictions from trees excluding it, then evaluate the loss. Too few trees can leave unstable or missing OOB predictions.

OOB evaluation is useful under an appropriate independent-row sampling setup. It does not emulate a future time period or a new organization, and repeated tuning against OOB scores still creates selection optimism. There is no universal theorem that its error is always slightly worse than five-fold CV.

Interpreting importance

Mean decrease in impurity sums sample-weighted impurity reductions attributed to a feature across trees. Many potential cutpoints can make a feature look important by chance, particularly on training data.

Permutation importance measures held-out performance degradation after shuffling a feature. It assesses dependence of this fitted predictor on that feature under a particular perturbation. Correlated substitutes can hide importance; shuffling can also create unrealistic combinations. Neither method proves causation or fair treatment.

Practice and pitfalls

Control Main tradeoff
Number of trees Stability versus memory and prediction cost
Features per split Lower correlation versus weaker trees
Minimum leaf size Smoother estimates versus missed fine structure
Maximum depth Complexity and latency versus fit
Bootstrap sample size Diversity versus information per tree

Classical heuristics include \(m\approx\sqrt d\) for classification and \(d/3\) for regression; these are not universal contemporary library defaults. Validate the chosen implementation’s settings. Unpruned deep trees are common, but bagging does not prohibit limiting depth or leaf size when data are noisy or small.

A forest of average-valued regression leaves cannot extrapolate outside the training response range. Large forests occupy memory and can have substantial latency. More trees mainly reduce Monte Carlo variability; they do not resolve leakage, distribution shift, or a poorly chosen feature representation.

Interview questions

Why introduce feature randomness after bootstrapping? Strong predictors can make bootstrap trees highly correlated; restricting candidate features diversifies their structure.

Can OOB replace a chronological test? No. A row’s exclusion does not prevent neighboring future observations from influencing its predictor.

Why does permutation importance drop for duplicate features? The unshuffled duplicate may supply nearly the same information.

Summary

Random forests combine row resampling and feature subsampling. Their effectiveness depends on both tree strength and dependence; OOB scores are an evaluation tool with a specific sampling scope.
