研究问题

模型何时适合协作，又该在哪个环节协作？

任务结构决定协作的位置：短上下文任务可以聚合答案，长篇章任务还可以共同选择证据。

先判断任务是否存在可共同筛选的中间证据，再选择协作方式。

研究设计

四个基准覆盖两类推理场景

比较短上下文推理与长篇章自然语言推断；每组方法对照使用同一批验证问题。

ConTRoL 提供了长篇章证据选择环节，短上下文任务中的这一空间则较有限。

短上下文结果

答案聚合未改善这些短上下文任务

在三个短上下文基准上，投票、辩论与裁判方法均低于 Qwen2.5-7B 直接回答。

错误相关与置信度失准是诊断解释，尚不能作为单独识别的原因。

转向长篇章

仅汇集证据，表现接近单模型检索

接着转向 ConTRoL：三个模型分别摘取原文语句，汇集证据后交给单个模型回答。

相对 RQA，这两组汇集方案分别变化 +0.1 和 −0.6 个百分点，因此进一步研究证据筛选。

证据协作架构

共享证据先核验，再由单个模型回答

核验实验改用 Qwen3-8B 回答；模型共同检索和检查证据，再选择一条回答路径。

保留证据作答与直接回答回退互斥，两条路径都保留原始输入，并使用同一个回答模型。

主要对照结果

完整 F1 流程提高6.2个百分点

固定 Qwen3-8B 为回答模型时，F1 准确率为71.7%，单模型检索基线为65.5%。

提升对应包含回退的完整 F1 与 RQA 的比较，不能单独归因于核验模块。

验证与解释

来自原文的证据，也可能无助于回答

F1 接受更少候选，也更常回退；字符级审计另行检查检索证据是否有原文支持。

证据接受率、回退率与原文支持度衡量不同性质；此项审计不衡量最终回答的幻觉率。

研究结论

让协作方式与任务结构相匹配

实验区分答案聚合、证据汇集和证据核验；结果来自不同任务与模型配置，需分别解释。

结果支持进一步研究证据环节的协作；跨任务推广与部署效率仍待验证。
